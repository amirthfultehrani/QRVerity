# QRVerity 1.0.0 Release Notes

> **QRVerity 1.0.0** — Private. Reliable. Open Source.

QRVerity 1.0.0 is the initial v1.0 release candidate of QRVerity, a privacy-first static QR code generator web application featuring pre-download rendered-output verification.

---

## Highlights

- **100% Client-Side Architecture**: Zero backend servers, databases, user tracking, or analytics. Payload validation, QR matrix encoding, canonical SVG rendering, logo sanitization, and verification run locally in your browser.
- **Pre-Download Optical Verification**: Final rendered SVG output is rasterized and decoded using `jsQR` inside a Web Worker before image export, generating deterministic **Predicted Reliability** assessments (`GOOD`, `CAUTION`, `RISKY`).
- **Strict Structural Safety**: Code invariants prevent decorative module styles or uploaded raster logos from occluding protected QR structural regions (finder patterns, separators, timing lines, alignment patterns, format/version blocks, dark module).
- **Nine Structured Content Formats**: Full support for URL, Plain Text, Wi-Fi, Email, Phone, SMS, vCard 3.0, Geo coordinates, and iCalendar 2.0 events.
- **Accessible & Cross-Browser**: Designed and tested toward WCAG 2.2 AA standards with full keyboard navigation, high-contrast focus rings, screen reader live regions, and Playwright test coverage across Chromium, Firefox, and WebKit (Safari).

---

## Privacy Model

- Payload serialization and QR matrix creation execute 100% locally.
- Uploaded raster logos are decoded locally on HTML Canvas to strip EXIF/IPTC/XMP metadata completely.
- Optical verification runs inside a same-origin Web Worker without remote API calls.
- Static hosting providers (e.g. GitHub Pages) serve application HTML/CSS/JS bundles over standard HTTP GET requests; QRVerity itself makes zero remote network calls after page load.

---

## Verification Model

- Verification converts canonical SVG to pixel-snapped ImageData and passes raw pixel buffers to `jsQR` with `inversionAttempts: 'dontInvert'`.
- Strict string equality (`===`) checks decoded text against canonical payload.
- Contrast ratio heuristics evaluate foreground/background color combinations.
- Unexpected worker/decoder exceptions transition execution state to `error` rather than masquerading as domain `RISKY` results.

---

## Supported Content Types

- **URL**: `http://` and `https://` web addresses.
- **Text**: Plain text messages.
- **Wi-Fi**: `WPA`, `WEP`, and open networks with reserved character escaping.
- **Email**: Mailto URIs with case-preserved local-part (RFC 5321) and lowercased domain.
- **Phone**: `tel:` phone numbers.
- **SMS**: `sms:` short message service payloads.
- **vCard**: vCard 3.0 contact cards with CRLF line endings.
- **Geo**: `geo:latitude,longitude` location points.
- **Calendar**: iCalendar 2.0 VEVENT objects with UTC timestamps and CRLF line endings.

---

## Customization & Exports

- **Module Styles**: Square, rounded, or dot data modules.
- **Finder Treatment**: Square or outer-corner rounded finders.
- **Logo Integration**: PNG, JPEG, and WebP raster logos (automatically forces ECC H and clamps footprint to 0 protected module collisions).
- **Exports**: Vector SVG file download, pixel-snapped PNG file download (256px to 2048px presets), Copy SVG to clipboard, Copy Image to clipboard (where supported by browser `ClipboardItem` API).

---

## Known Limitations

- **Predicted Reliability is Not a Guarantee**: Verification tests rendered output under QRVerity test conditions in your browser; physical scanning depends on external camera hardware, lighting, printing materials, and distance.
- **No Transparent Backgrounds in v1**: Background color options require opaque colors to ensure contrast calculations remain deterministic.
- **Raster Logos Only**: SVG logo uploads are forbidden to eliminate vector script/xss risks.
- **Static App Hosting Header Limitations**: Static hosts such as GitHub Pages enforce CSP via HTML `<meta>` tags rather than HTTP response headers (`frame-ancestors` and non-meta directives are not active).
- **Clipboard Image Support**: Copying PNG images directly to clipboard depends on browser support for `ClipboardItem` with `image/png` MIME types.
