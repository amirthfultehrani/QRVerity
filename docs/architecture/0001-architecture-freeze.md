# 0001. Architecture Freeze

These decisions are immutable baseline decisions for **PureQR**. They are frozen unless explicitly altered by the repository owner.

---

## Immutable Decisions

1. **Stack**: Preact + TypeScript strict mode + Vite.
2. **QR Encoder**: Nayuki QR-Code-generator TypeScript implementation will eventually be the ONLY QR encoder.
3. **Vendoring**: Nayuki will be vendored in `src/qr/vendor/` and pinned/documented by upstream commit.
4. **Adapter Isolation**: Exactly ONE PureQR adapter module (`src/qr/`) will be allowed to import the vendored Nayuki implementation. No UI, renderer, payload, exporter, verifier, or other module may import Nayuki directly.
5. **Canonical Geometry**: `QrMatrix` is the canonical source of QR geometry.
6. **Structural Region Map**: PureQR will own a QR structural-region map derived from QR version geometry covering finder patterns, separators, timing patterns, alignment patterns, format information, version information, and fixed dark module where applicable.
7. **Hard Structural Protection**: Structural protection is a HARD invariant. Styling must not silently corrupt protected regions. Logos must NEVER overwrite protected regions. If requested logo dimensions conflict with protected regions, logo placement logic must shrink/clamp/refuse the requested size. It must NOT simply render an unsafe logo with a warning.
8. **Quiet Zone**: Minimum quiet zone is strictly 4 modules.
9. **Renderer**: PureQR will use a custom SVG renderer.
10. **Canonical Visual Output**: `QrMatrix` is canonical geometry; the generated final SVG is canonical visual output.
11. **Canvas Role**: Canvas must NEVER become an independent QR renderer or source of truth. Canvas is downstream only for rasterization, PNG export, and verification.
12. **Single SVG Derivation**: SVG export and PNG export must derive from exactly the same canonical SVG representation used by verification. Never recreate QR geometry separately for exports.
13. **SVG Simplicity**: SVG generated by PureQR must remain simple (`svg`, `rect`, `path`, `circle`, presentation attributes, absolute geometry). Avoid `foreignObject`, external SVG resources, external stylesheets inside SVG, scripts, event handlers, remote images, or unnecessary filters.
14. **Decoder Library**: Verification will use `jsQR`.
15. **Pre-Verification Rasterization**: Final styled SVG will be rasterized BEFORE verification.
16. **Worker Boundary**:
    - **MAIN THREAD**: Payload validation/serialization, QR encoding, structure-map generation, SVG creation, SVG -> Canvas/ImageData rasterization, PNG generation, browser clipboard/download APIs, UI.
    - **WORKER**: `jsQR` decode, payload comparison, pure reliability calculations.
    - Do not architect the system assuming SVG rasterization inside a Web Worker.
17. **Transferable Buffers**: Pixel buffers should be transferred to workers using transferable `ArrayBuffer` objects where practical.
18. **Pixel Snapping**: Rasterization/export dimensions must snap to an integer number of pixels per module. Total symbol includes matrix width + quiet zone on both sides. Avoid fractional module boundaries causing anti-aliasing artifacts.
19. **Transparency Verification**: Transparent exports remain transparent. Verification of transparent output will composite the QR onto an explicit verification backdrop (e.g., white) before `jsQR` runs. Reliability UI must warn that actual reliability of a transparent QR depends on its backdrop.
20. **Logo Policy (v1)**:
    - PNG/JPEG/WebP raster logos only, decoded and re-rasterized locally (metadata stripped).
    - Recommended <=15% area; absolute maximum ~20% subject to structural safety.
    - Safe maximum dynamically clamps against protected regions.
    - Presence of logo forces Error Correction Level H before version/structure calculation.
21. **Explicit Decoder Configuration**: `jsQR` options must be explicitly configured without relying on library defaults.
22. **Predicted Reliability UI**: Label must strictly use `Predicted Reliability` with states `GOOD`, `CAUTION`, `RISKY`. Never claim "Guaranteed Scannable", "Guaranteed to Scan", "100% Scannable", or equivalent.
23. **Multi-Size Verification**: Verification architecture must support `number[]` raster sizes, proving one size first (e.g., 256, 512, 1024).
24. **Payload Comparison Strategy**: Baseline comparison is the EXACT canonical serialized payload string passed to QR encoder. Fuzzy comparison must never silently hide a mismatched payload.
25. **v1 Payload Types**: URL, Plain Text, Wi-Fi, Email, Phone, SMS, vCard, Geographic coordinates, Calendar event.
26. **v1 Exports**: SVG, PNG, Copy SVG, Copy image (where supported). No PDF, no WebP.
27. **v1 Appearance Options**: Foreground color, background color, transparent background, square data modules, mildly rounded data modules, dot data modules, square finders, conservative limited-rounded finders, raster logo, logo backing/padding, logo size. No gradients, background images, animated QR, SVG logos, or arbitrary finder geometry.
28. **Derived Data Rules**: Derived QR data (serialized payload, matrix, metadata, role map, SVG, ImageData, verification result, reliability result) is NEVER primary writable application state; it must be recomputed or memoized from user-controlled state.
